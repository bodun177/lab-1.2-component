# Звіт з лабораторної роботи 1.2

## 1. Відомості про роботу

- **Номер і тема:** лабораторна робота 1.2 — «Розроблення компонентної
  архітектури та повторно використовуваних компонентів».
- **Мета:** розвинути початковий ReactJS застосунок у зрозумілу компонентну
  архітектуру: визначити відповідальності компонентів, передавання даних через
  `props` і поєднання інтерфейсу через композицію, створити повторно
  використовувані елементи без копіювання розмітки.
- **Назва індивідуального застосунку:** «Автозапчастини» — вебзастосунок для
  пошуку та підбору автомобільних запасних частин.

## 3. Розвиток результату Л 1.1

У Л 1.1 застосунок містив демонстраційні компоненти `Hello`, `Goodbye`,
`Counter` і `Title`, сторінки `Home` та `About`, а навігація й розмітка
заголовка були вбудовані в `App`. Сценарій перегляду збережено: користувач
відкриває головну сторінку, читає опис застосунку, переходить до каталогу та
на сторінку «Про застосунок».

Демонстраційні компоненти замінено предметним поданням: `Title` залишено як
спільний заголовок застосунку (styled-components із Л 1.1), а `Hello`,
`Goodbye` і `Counter` прибрано, більше не потрібні для сценарію каталогу —
їхню роль перебрали `SiteHeader` і `Section`. Інтерактивність (стан,
пошук, фільтри) за планом належить до Л 2.1, тому в цій роботі інтерфейс
статичний. Історія змін збережена в Git.

## 5. Характерні фрагменти коду

### 5.1. Передавання даних через props

Сторінка поєднує локальні дані з поданням і не містить розмітки картки:

```jsx
// src/pages/HomePage.jsx
<Section id="catalog" title="Каталог запчастин">
  <CatalogSummary total={parts.length} />
  <PartList items={parts} />
</Section>
```

```jsx
// src/components/parts/PartList.jsx
{items.map((item) => (
  <li key={item.id}>
    <PartCard item={item} />
  </li>
))}
```

Ключем є стабільний `item.id`, а не індекс масиву. Порожній масив
обробляється окремо через `EmptyState`.

### 5.2. Композиція через children

`Section` відповідає лише за заголовок, `id` і зв'язок `aria-labelledby`,
а вміст отримує через `children`; `AppLayout` так само не імпортує сторінки:

```jsx
// src/components/ui/Section.jsx
export default function Section({ id, title, children }) {
  const titleId = `${id}-title`
  return (
    <section id={id} aria-labelledby={titleId}>
      <h2 id={titleId}>{title}</h2>
      {children}
    </section>
  )
}
```

```jsx
// src/components/layout/AppLayout.jsx
<main id="main-content" tabIndex={-1} className="app-main">
  {children}
</main>
```

### 5.3. Усунення дублювання правила наявності

До рефакторингу умова наявності була б у картці та на сторінці підбору. Тепер
правило існує в одному компоненті й використовується у двох місцях:

```jsx
// src/components/parts/AvailabilityBadge.jsx
export default function AvailabilityBadge({ available }) {
  const label = available ? 'Є в наявності' : 'Немає в наявності'
  const className = available ? 'status available' : 'status unavailable'
  return <span className={className}>{label}</span>
}
```

`PartCard` (каталог) і `SelectionPage` (приклад результату підбору) показують
той самий статус; зміна тексту виконується в одному файлі.

## 6. Обґрунтування поділу

- **Компонування (`AppLayout`, `SiteHeader`, `MainNav`)** відокремлене від
  вмісту: шапка, навігація, `main` і підвал не змінюються під час розвитку
  сторінок. `MainNav` отримує масив `{ to, label }` і не знає, які сторінки
  існують.
- **Сторінки (`HomePage`, `SelectionPage`, `AboutPage`)** — єдине місце, де
  локальні дані зустрічаються з поданням: імпорт масиву й передавання `items`
  та `part`. Картка не імпортує каталог і не шукає запис за індексом.
- **Предметні компоненти (`PartCard`, `PartList`, `AvailabilityBadge`,
  `CatalogSummary`)** знають модель запчастини та правила її подання.
- **Спільні UI компоненти (`Section`, `EmptyState`, `AppButton`, `FormField`,
  `Title`)** не знають предметної області: `EmptyState` використано для
  порожнього каталогу та для відсутнього запису в підборі, `FormField` — для
  чотирьох полів форми, `AppButton` — для двох кнопок, `Section` — у п'яти
  місцях. Напрям залежностей: `pages → components → ui`, тому заміна джерела
  даних у Л 3.2 не потребує змін у поданні.
- **Оформлення:** власні CSS класи в `src/index.css` (прості для перевірки, без
  нових залежностей) і наявний `styled-components` лише для заголовка
  застосунку. React Bootstrap не підключався: базових стилів достатньо, а
  глобальні стилі бібліотеки ускладнили б узгодження з наявними правилами.
- **Маршрутизація:** React Router уже використовувався в Л 1.1, тому
  збережений; сторінки підключені як елементи `Route`, а `MainNav` працює з
  `to`, щоб перехід не перезавантажував сторінку.

## 7. Перевірка результату

| Дія                                              | Очікуване спостереження                                      | Результат |
| ------------------------------------------------ | ------------------------------------------------------------ | --------- |
| Відкрити `/`, перейти за посиланнями навігації    | доступні каталог, підбір запчастини й сторінка «Про застосунок» | успішно   |
| Змінити `name` та `available` запису в даних      | картка показує нові значення, статус узгоджений в обох місцях  | успішно   |
| Тимчасово передати `items={[]}` у `PartList`      | видно повідомлення «Запчастини ще не додано.»                  | успішно   |
| Тимчасово передати `part={undefined}`             | видно пояснення відсутності предмета, форма не ламається       | успішно   |
| Натиснути «Очистити» у формі підбору              | поля очищуються, сторінка не перезавантажується                | успішно   |
| Перейти клавішею Tab, натиснути підпис поля       | фокус видимий, підпис пов'язаний із полем                      | успішно   |
| Звузити вікно (1280 → 400 px)                     | картки переносяться, вміст не перекривається                   | успішно   |
| `npm run build`                                   | «Compiled successfully», без помилок імпортів і JSX            | успішно   |

Виявлені під час роботи проблеми та виправлення:

1. Збірка падала з `no-unused-expressions` у `src/data/parts.js`: масив було
   записано без оголошення `export const parts`. Виправлено оголошенням
   змінної та додаванням похідного списку `categories`.
2. Посилання «Перейти до вмісту» було постійно видимим і зсувало шапку.
   Виправлено приховуванням поза екраном до отримання фокуса.
3. На короткій сторінці «Про застосунок» підвал піднімався вгору. Виправлено
   flex-компонуванням `#root` з `min-height: 100vh`.
4. Картка результату підбору розтягувалась на всю ширину секції. Обмежено
   контейнером `.result-preview` (22 rem).
