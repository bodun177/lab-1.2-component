# План проєкту: «Автозапчастини»

## Тема

Розробка вебзастосунку для пошуку та підбору автомобільних запасних частин.

## Мета

Дати користувачу змогу переглянути каталог запчастин, оцінити наявність і ціну
та підібрати деталь за маркою, моделлю й роком випуску автомобіля.

## Цільові користувачі

- власники автомобілів, які шукають конкретну деталь;
- майстри станцій технічного обслуговування, які підбирають запчастини клієнтам.

## Сторінки

| Маршрут      | Призначення                                             | Стан у Л 1.2        |
| ------------ | ------------------------------------------------------- | ------------------- |
| `/`          | Опис застосунку та каталог запчастин                    | реалізовано         |
| `/selection` | Підбір запчастини за автомобілем, макет форми           | реалізовано (макет) |
| `/about`     | Відомості про застосунок і стек                          | реалізовано         |

## Модель даних

Запис каталогу `part` містить поля:

| Поле          | Тип      | Призначення                                  |
| ------------- | -------- | -------------------------------------------- |
| `id`          | `string` | стабільний ідентифікатор, ключ списку        |
| `name`        | `string` | назва запчастини                             |
| `article`     | `string` | артикул виробника                            |
| `brand`       | `string` | марка автомобіля, для якої підходить деталь  |
| `category`    | `string` | категорія (гальмівна система, фільтри тощо)  |
| `price`       | `number` | ціна в гривнях                               |
| `available`   | `boolean`| наявність на складі                          |
| `description` | `string` | короткий опис                                |

Початкові записи зберігаються в `src/data/parts.js`. Категорії для форми
підбору обчислюються з того самого масиву, щоб не дублювати перелік.

## Етапи

1. **Л 1.1** — створення застосунку, базові компоненти, стилі, маршрутизація. Виконано.
2. **Л 1.2** — компонентна архітектура: компонування, навігація, сторінки,
   предметні та спільні UI компоненти, контракти props, документація. Виконано.
3. **Л 2.1** — стан, хуки, пошук і фільтри, керовані поля форми підбору.
4. **Л 2.2** — маршрути з параметрами (окрема сторінка запчастини).
5. **Л 3.1** — створення, редагування та видалення записів, валідація.
6. **Л 3.2** — асинхронне джерело даних замість локального масиву.

## Критерії готовності Л 1.2

- каталог і сторінка підбору доступні з навігації;
- список, картка, статус наявності, секція, кнопка й поле форми виділені в
  окремі компоненти;
- контракти props описані в `docs/component-architecture.md`;
- спільні компоненти використані щонайменше у двох змістовних місцях;
- `npm run build` завершується без помилок.
